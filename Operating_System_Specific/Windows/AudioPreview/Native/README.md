# Windows native audio preview

`WindowsAudioDevices.EnumerateOutputs()` reads connected playback endpoints. Bluetooth classification follows the physical adapter's PnP ancestry; a friendly name is never sufficient evidence. Unknown transport stays unknown. `IsSpeakers` comes from the driver's endpoint form factor. Native identifiers and endpoint names are local data and must not appear in published fixtures or logs.

Constructing an audio session does nothing until `Start()` is called. `WasapiSystemCapture` captures other applications' playback through Windows process loopback, excluding the preview process and its descendants. There is no microphone capture. Exclusion prevents received audio rendered by this process from being captured and sent back. Capture delivers fresh, finite 480-frame stereo float blocks at 48 kHz. A subscriber must queue work without waiting for a network write.

`WasapiOutput` plays on the explicitly selected endpoint. `SetFrameProvider` pulls a 10 ms block from the mixer using the endpoint's WASAPI event clock, retaining a partial block when the driver asks for fewer frames. The Windows audio engine converts this fixed format to the physical endpoint's format. Diagnostic `TryWrite` uses a bounded 200 ms buffer and rejects overflow. Missing mixer data produces silence. A disconnect or driver error stops the session and reports `Faulted`; it never silently switches to another output.

No API changes system defaults, pairs Bluetooth devices, or mutes another application. Original local playback continues. The routing owner must skip replaying local audio on its existing default endpoint and must stop sessions when consent is withdrawn, the peer disconnects, or the machine suspends. This is a Windows 11 preview; process-loopback activation failures disable capture rather than falling back to endpoint loopback.

`AudioNativeTests` uses synthetic samples and ABI checks. `--enumerate-count` additionally performs read-only device enumeration without printing names or identifiers. Neither test path starts capture or playback. Live audio and unplug validation remain required before release.
